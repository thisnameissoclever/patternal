## What works

- [S1] One body everywhere. The in-app preview, the packaged assets and the live simulation all use the MakeHuman MPFB2 body, with CC0 output. The CharMorph Antonia path is retired from the live pipeline, the runtime manifest and the installer.
- [S2] The Simulate flow ran all sixteen stages on 2026-09-13 and the final settle was accepted: equilibrium at frame 222 after a 180-frame animation from the rest body to the arms-lowered body, zero body collisions, zero self collisions, zero seam separation.
- [S3] That run ends on "Six views await your review". This is the designed stop: `visual_quality.accepted` in the proof manifest is written only by a person, through `tools/record_product_visual_review.py`.
- [S4] The avatar preview responds to 97 measurement dimensions through a packaged sparse morph basis (`Patternal/Assets/Production/Avatar/mpfb-morphs.bin`, 85 parameters).
- [S5] The viewport shader works in linear light with hemisphere ambient, wrapped diffuse on skin, a filmic tone map, fold occlusion on cloth and smooth normals across UV seams.
- [S6] The bra shell no longer reaches out to the arms. Verified on 2026-11-16 by running the generator directly and rendering its output: the shell spans 18.9 cm either side of the midline, where it spanned 41.2 cm.
- [S7] `dotnet build .\Patternal\Patternal.csproj -p:Platform=x64` gave 0 warnings and 0 errors on 2026-11-16. `node tools/test_avatar_sparse_morph_basis.mjs` passes. `python -m unittest tools.test_promote_style3d_baseline tools.test_mpfb_local_deformations`, run from the repository root with the runtime's GarmentCode interpreter, ran 8 tests with no failures.

## What is broken

- [B1] Job resume ignores runtime script changes. `CanResumeAcceptedStyle3DEquilibrium` in `Patternal/SimulationPipeline.cs` reuses a job's cached stage outputs when the pattern, body and solver reports match, and does not notice that a generator script changed. On 2026-09-13 this made a verification run render stale avatar assets and look like a pass. Until it is fixed, move the revision's job directory aside before any run meant to exercise a changed script.
- [B2] The visual result would fail an honest review. See [V1] to [V5].

## Visual gaps

- [V1] No briefs. The lower body renders nude. MakeHuman's CC0 clothes library is installed in the runtime under `third_party/MakeHumanAssets` and could supply one.
- [V2] The tee reads as a boxy crop top, and the cloth pinches into a hard fold between the bust and the waist. The first is the drafted pattern and its ease. The second is not diagnosed.
- [V3] The face is lit paler than the body, and the hair is flat grey.
- [V4] The arms are lowered only 12 degrees from the A-pose, so the figure does not read as standing naturally. A larger angle needs its own trajectory and contact proof; see the pose item in `TODO.md`.
- [V5] The bra shell is fitted on the rest body and is not posed with it. No poke-through shows under the tee in the check views. Not checked with the garment hidden.

## Environment checks

Observed on 2026-11-16 on a Windows 11 Pro desktop, build 26300.

- Simulation runtime. Check with `Get-Content "$env:LOCALAPPDATA\Patterna\SimulationRuntime\current\runtime-manifest.json" -TotalCount 12`. Expect `runtimeVersion` `2026.09.13-style3d-mpfb-v1` and `avatarBackend` `MakeHuman MPFB2`. If it is absent, or after changing any file under `tools`, reinstall with `.\tools\install_patterna_simulation_runtime.ps1 -SourceRoot <repository root> -Replace`. The `-SourceRoot` argument is required; without it the script resolves an empty root. Observed: installed, with `tools\generate_mpfb_avatar.py` identical to the repository copy.
- Job directories live under `%LOCALAPPDATA%\Packages\<package family name>\LocalState\SimulationJobs`, one folder per revision hash. Find the package family name with `Get-AppxPackage | Where-Object InstallLocation -like '*Patternal*'`. Observed: package family `C513E361-86E8-4FBD-9FF7-FABA0EAFA8FE_1z32rh13vfry6`, newest job `47bf3c0d8f81...`, last written 2026-09-13 and holding the stale avatar assets.
- Registered app payload. The app runs from a loose-layout `AppX` folder that `dotnet build` does not refresh. Compare `LastWriteTime` of `Patternal.dll` in `Patternal\bin\x64\Debug\net10.0-windows10.0.26100.0\win-x64` and in its `AppX` subfolder. If they differ, launch with `dotnet run --project .\Patternal\Patternal.csproj -p:Platform=x64 --no-build`, which restages first. Observed: the `AppX` copy was from 2026-09-13 and did not yet contain the 2026-11-16 pipeline change.
- Standalone generator check, about three minutes: `& "$rt\blender\blender.exe" --background --python-exit-code 1 --python tools\generate_mpfb_avatar.py -- --profile <job>\avatar-garmentcode-profile.json --output <dir>\avatar-mpfb.obj --render-output-dir <dir>\display-avatar --render-asset-root "$rt\third_party\MakeHumanAssets\makehuman_system_assets"`, with `$rt` the runtime folder. Do not pass `--factory-startup`; it disables the MPFB extension.
- Python tests under `tools` import `tools.<module>`, so run them as modules from the repository root: `python -m unittest tools.test_promote_style3d_baseline`. Running the file directly fails with `ModuleNotFoundError`. The host Python had no `pytest`; the runtime's `.venv-garmentcode` interpreter has the dependencies.
- When driving the app through UI Automation, find controls by AutomationId. The 3D tab is `Workspace3DTab`; its visible name "3D DRAPE" is not unique.
- Nothing from this work was left running.
