# Patternal architecture v2

> Historical implementation record. The evidence-backed replacement boundary and migration plan are in [architecture-v3-reassessment.md](architecture-v3-reassessment.md). This file remains authoritative for how the current implementation was assembled, but it is not a declaration that the current avatar, cloth, or packaged UX meets the CLO-class target.

Last reviewed: 2026-07-23

## Decision

Patternal will not use the custom `FullGarmentArrangement` circumference-shell deformation as its production garment dressing system. That prototype can remain available only for regression evidence until its callers are removed.

The production stack is:

1. WinUI owns the project workflow, measurements, editable pattern UI, history, and export commands.
2. A GarmentCode-compatible pattern kernel owns panels, curves, interfaces, seams, darts, annotations, grading rules, and stable identifiers. Patternal may translate to and from PyGarment JSON instead of embedding its GUI.
3. Pattern pieces enter 3D as separate, collision-free panels with explicit sewing constraints. Rigid transforms and strain-free cylindrical bends may reduce sewing travel, but the compiler must not stretch panels or force front and back seams to zero gap through a body before simulation.
4. MPFB owns the current measurement-fitted female body topology. One evaluated MPFB surface is shared by drafting, Style3D collision, and compiler preflight. The display body preserves that exact evaluated surface and stable topology while adding the original MakeHuman UV layout and fitted visual assets.
5. Newton `SolverStyle3D` owns the currently accepted static equilibrium. The product displays the compiler-refined render surface derived from that exact equilibrium until a downstream interactive solver passes equivalent seam, contact, strain, and visual gates.
6. Unreal 5.8 `ChaosOutfitAsset` remains the target for resizable packaging, multiple source-body sizes, render meshes, and animation. Chaos Cloth refinement is diagnostic-only while its seam handoff is rejected. A later offline C-IPC lane owns slow, high-accuracy contact validation.

## Historical Blender cloth architecture reset validation

The earlier packaged Warp equilibrium did not prove believable drape. Patterna retains a reversible Blender 4.5.9 LTS validation lane with separate simulation and render surfaces as historical regression evidence. The accepted 7,698-vertex Warp panel surface supplied regular physical triangles and collision-free body registration. Blender Cloth refined that proxy against the same evaluated body, and Surface Deform transferred the result to the detailed pattern-UV render surface. Physical diagnostics used thin simulation and render surfaces; the 0.34 mm Solidify shell was visual only.

The original direct-render-mesh proof materially replaced the rigid box silhouette with gravity-led wrinkles, but it contained UV-split micro-edges and failed the refinement-strain gate. Automatic remeshing either timed out or created degenerate boundary edges, and raw loose-edge panel sewing produced gathering, open junctions, body crossings, and spikes. Those routes are rejected. The corrected dual-surface proof passes independent CUDA diagnostics with zero simulation-body crossings, zero render-body crossings, and zero cloth self-intersections. Its best bounded-strain run remains rejected because final motion exceeds the 0.50 mm maximum and 0.05 mm mean per-frame gates, and visual review still finds a bridged bust and crowded sleeve junctions. This lane becomes a production candidate only after motion, exact contact, strain, seam, and multi-view visual gates all pass for the same revision.

This result changes the solver boundary, not the product model. WinUI continues to own measurements and authoring, and the GarmentCode-compatible source remains the authority for patterns and seams. A direct pattern-panel path now exports independent regular panel triangles and explicit sewing springs for continued arranger work, but it is not a replacement for the accepted Warp arrangement. Blender is allowed to become the garment simulation backend only if it preserves source correspondence and produces a materially better accepted visual result. A post-process that merely smooths an unrelated mesh is not sufficient.

Physical topology is now an immutable schema 2.6 solver input. Every new report binds the copied pattern specification and mesh resolution, raw physical OBJ, ordered face connectivity, position-to-pattern corner mapping, material rest graph, per-particle panel ownership, combined welded and explicit seam-constraint graph, mesher source, solver source, and final output OBJ. The rest-pose and posed passes must match all structural and implementation hashes before the application can reuse or compile the result. This closes the gap that allowed one pattern hash to describe both an 8,664-particle welded surface and a 9,132-particle explicit surface.

Replaying the legacy side-dart proof on its exact welded BoxMesh reproduced all 8,664 positions, 17,095 faces, 9,132 pattern-space vertices, and the original raw physical-mesh SHA-256. It also exposed that the legacy schema 2.3 acceptance covered only 23,523 structural edges. Evaluating both the old accepted output and the current 215-frame replay against all 25,761 authored material edges produces approximately 51.35 percent peak strain, not the recorded 38.40 percent. Extending the replay to 650 frames retains zero body and self crossings but reaches only 45.33 percent peak strain. The legacy result therefore remains regression evidence and cannot be promoted under schema 2.6. Explicit sewn-panel topology remains the production target, and it still requires an accepted arrangement and drape result.

The explicit topology investigation now separates three previously conflated failures. Panel-space barycentric transfer can move a collision-clean drape between different physical tessellations while recording the source pattern and topology; the 0.8 cm refinement proof starts with zero body and self crossings and less than 0.029 cm material projection error, but resolution alone does not fix underarm strain. Seam components are now explicit deterministic solver inputs. Production promotion is blocked until material, contact, and multi-way seam constraints are coupled within one iterative solver or replaced by a validated solver backend. No threshold or strain edge is excluded.

## Why the original garment failed

The original compiler placed each panel on an analytic torso shell, averaged paired seam positions, spread those displacements across the full panel, and repeatedly relaxed edges while forcing every sewn pair to one point. Front-to-back seam midpoints fell inside the avatar. Vertex-only radial projection did not prevent triangles from folding through the body. The acceptance checks measured seam gaps, vertex clearance, and edge strain, but did not reject crossed panels, reversed surface orientation, triangle-body intersections, or an incorrect garment silhouette.

The resulting static pose already contained the missing neckline, crossed back, abdominal opening, and hip holes before cloth simulation. Chaos then simulated invalid input.

## Body-specific garment pipeline

The current upper-body path is:

1. Patterna measurements and manual overrides update the measurement profile.
2. MPFB evaluates the profile into one exact female body surface and stable rig-weight segmentation.
3. Patterna validates the watertight surface and writes the GarmentCode body YAML, exact collider, segmentation, and compiler body profile from that same mesh.
4. GarmentCode generates editable two-dimensional panels and semantic sewing interfaces from the selected style and body YAML.
5. GarmentCode `BoxMesh` produces remeshed panel topology and explicit stitch pairs.
6. NVIDIA Warp runs the first XPBD equilibrium against the measured rest-pose body and writes normalized body-contact, self-contact, and strain metrics.
7. Patterna applies the MPFB rig to the fitted body, textured display body, and already sewn sleeve panels together. Torso panels remain fixed, sleeve panels move rigidly, and shared stitch vertices receive the interpolated shoulder transition.
8. Warp resettles the posed garment against the posed body using the original edge-length pickle and original box mesh as the material-strain authority.
9. The .NET garment compiler imports the panel topology and accepted relaxed-pose positions, preserves panel and seam identifiers, and writes OpenUSD plus a hashed manifest.
10. WinUI renders the accepted welded surface directly. Unreal may import that state for packaging and bounded interactive refinement only after it passes the same acceptance gates.

Each job is immutable and revision-addressed. MPFB fitting, rest-pose body conversion, segmentation, body-profile sampling, pattern export, mesh generation, rest-pose Warp dressing, collision-body pose generation, display-avatar pose generation, animated-body Warp resettling, compiler preflight, USD generation, manifest generation, and welded render export logs remain together. Failure at any stage leaves the prior asset hidden for the current revision. Accepted cache validation rehashes the body pose and preparation reports, the rest-pose Warp report, the staged accepted garment, original edge-length pickle, original box-mesh strain reference, animation-start body, final body, and final Warp report before reusing a result. The accepted baseline records bounded body and self contact, peak, broad, and localized strain, completed body animation, a hashed solver configuration, and a 0.34 mm cotton source. Apparent thickness remains a visual acceptance issue as well as a numeric material property.

The acceptance boundary is intentionally split. Authored 2D panels must be simple boundaries before meshing. Curvature-adaptive tessellation limits segment length without creating sliver triangles along nearly straight cubics. GarmentCode seam junction placement uses the true weighted centroid of every participating local vertex instead of stitch-order-dependent repeated averaging. Warp refreshes body and self-collision contacts inside every integration substep and rejects saturated contact storage. Warp pre-fitting must pass normalized contact plus peak, 95th-percentile, and 99.9th-percentile strain gates before interchange. Candidate search also rejects unfinished construction, implausible torso ease ranges, centering error, wrong hem height, upward-projecting sleeves, and left-to-right sleeve asymmetry. The compiler treats a validated immutable Warp report as the authority for the exact solved surface, uses the report's recorded strain limits within fixed compiler safety ceilings, and does not re-reject zero-collision cloth through the analytical preview-profile clearance heuristic. The runtime selects the newest built compiler assembly rather than preferring a stale Debug executable. The revision-specific shirt uses full front and back torso pieces with independent chest, waist, and hip ease plus sewn collar and cuff panels. A separate fitted waistband is not used as a shirt-length extension because that creates an artificial horizontal join and peplum-like flare. The compiler-native OBJ writes centimeters directly in the renderer's Y-up coordinate contract and records its SHA-256 hash beside the USD hash. The reference simulation artifact contains 30,591 surface vertices, 182,316 face-varying UV corners, 34 construction-seam strips, and 10 finished open edges. The WebView rejects legacy accepted revision caches that lack texture coordinates or either construction group. Unreal asset validation must match simulation counts loaded from the same manifest. A fresh packaged multi-angle pass remains mandatory for every promoted custom revision because application-layer camera, overlay, and material defects are separate visual gates from simulation acceptance.

The packaged startup baseline is intentionally a different artifact from an accepted simulation revision. It begins with the MakeHuman `female_casualsuit02` clothing proxy generated against the same MakeHuman body family as the display avatar. The generator keeps only the connected upper-garment components and preserves the source face-corner UV records. `tools/fit_mhclo_garment.py` then moves only vertices that are inside or closer than the requested clearance to the exact watertight final body. It preserves OBJ face and UV indexing, converts the result into the renderer's centimeter and Y-up contract, and writes a hash-bound `patterna.mhclo-garment-fit/1.0` report. The current default contains 1,311 positions and 5,048 face-corner UV records. Its accepted fit has 0 final inside vertices, 0.982 cm minimum clearance, 1.703 cm maximum displacement, and 0.635 cm mean displacement among corrected vertices. This report proves registration and clearance only. It does not claim material rest state, sewing closure, equilibrium, stress, strain, pressure, or correspondence to the editable 14-panel pattern. WinUI labels it as `BODY-AWARE PRODUCTION FIT`, hides it after any body, pattern, assembly, or fabric edit, and shows physics evidence only after the exact new source revision passes the GarmentCode and Warp pipeline.

The product-facing visual boundary has its own deterministic Blender proof. `tools/render_product_acceptance.py` imports the same display-avatar manifest, textured body, eyes, teeth, brows, lashes, hair, fitted startup garment, display UVs, and fabric image that WinUI packages. Display-avatar assets declare Blender meter coordinates with Z up, while the fitted garment declares centimeters with Y up; the renderer applies those conventions explicitly instead of treating every OBJ alike. Before rendering, it refreshes Blender transforms and applies the shared `patterna.product-registration/2.0` gate. That gate requires the avatar to stand on the studio floor and checks garment hem, neckline, and vertical span as fractions of the measured avatar height in addition to absolute overlap and horizontal centering. A translated avatar therefore cannot pass merely because both meshes still occupy plausible world coordinates. The proof emits six fixed-camera PNGs plus hashes for every source and output. `tools/test_product_acceptance_artifacts.py` verifies those hashes, camera coverage, image dimensions, nonempty output, the registration gate, the exact fit-report output hash, the watertight production-body hash, zero final inside vertices, and the minimum clearance. This proof does not replace packaged pixel review, but it prevents coordinate, asset, and evidence drift from reaching that review.

For revision-specific Warp results, the compiler also owns a separate display-surface refinement stage. The accepted Warp mesh remains the simulation authority and is never cosmetically rewritten. After construction seams are welded for rendering, the compiler classifies finished boundaries and non-manifold regions, freezes those protected vertices, applies three bounded Taubin fairing passes to remove mesh-frequency spikes without volume collapse, and performs one Loop subdivision for a continuous high-density display surface. Pattern UVs remain face-varying, so welding and fairing do not erase panel-space texture boundaries. The manifest records the algorithm, protected counts, and maximum and average base-vertex displacement. Revision promotion additionally runs an independent CUDA cloth-edge versus avatar-triangle intersection diagnostic against the refined OBJ and requires zero crossings. That evidence records both source hashes and topology counts, and the revision acceptance test rejects any mismatch between the OBJ, compiler manifest, collision body, and diagnostic report. This makes smoothing a reversible, measured render handoff rather than a substitute for cloth physics.

## Required acceptance gates

1. The 2D panel compiler preserves drafted lengths, curves, named edges, grain, and stable identifiers.
2. Initial 3D panels are separate, correctly oriented, and free of body and panel intersections.
3. Sewing constraints assemble the garment during simulation without welded-through-body initialization.
4. Garment closures such as ties, buttons, zippers, buckles, hooks, and temporary pins have explicit constraints separate from permanent construction seams.
5. A static turntable has zero triangle-body penetration and no self-intersection above tolerance.
6. The same checks pass in walking, sitting, arm-raised, and bent poses.
7. At least three materially different target bodies resize from the best source size without body breakthrough or inverted triangles.
8. The detailed render mesh retains thickness, seams, topstitching, trims, UVs, and materials while the simpler simulation mesh drives it, with no visible discontinuity across a sewn panel boundary.

## Migration sequence

2. Replace `FullGarmentArrangement` output with collision-free panel staging plus explicit sewing constraints.
